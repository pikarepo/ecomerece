Plain-language glossary for apps/api · packages/domain · packages/contracts
#WordIn plain wordsWhere it lives here
01 Aggregate The one object allowed to change the thing it models. It checks its own rules and writes down what happened while doing it. packages/​domain/​modules/​<name>/​<name>.aggregate.ts
02 Value object A small value that validates itself when created: Quantity.create(30) returns a valid quantity or throws. If it exists, it is valid. packages/​domain/​value-objects/​
03 Domain event A note the aggregate writes the moment something happened — “this was created, by this actor”. Nothing is sent anywhere until the save succeeds. packages/​domain/​modules/​<name>/​events/​
04 Repository port The interface the domain asks for, in domain words: find one, save one. It contains no database code at all — that is the point. packages/​domain/​modules/​<name>/​ports/​i-<name>-repository.ts
05 Adapter The class that fulfils a port with a real technology. Here: Mongoose. Swap the adapter, the domain does not notice. apps/​api/​modules/​<name>/​infrastructure/​<name>.repository.ts
06 Mapper The translator in both directions: aggregate → document, document → aggregate. It is the only place that knows both shapes. apps/​api/​modules/​<name>/​infrastructure/​<name>.mapper.ts
07 Read model The flat object you actually send to a client. Built for reading — no rules, no methods that change anything. packages/​domain/​modules/​<name>/​read-models/​
08 App service One use case per method. The shape here is always: load the aggregate → call one verb on it → save it → publish what it recorded. apps/​api/​modules/​<name>/​application/​<name>.app.service.ts
09 Controller Translates a request into arguments and the answer into a status code and JSON body. No business rules are allowed here. apps/​api/​modules/​<name>/​presentation/​<name>.controller.ts
10 Module factory Builds every object one module needs, in dependency order, and registers that module's handlers on the buses. apps/​api/​modules/​<name>/​<name>.module.ts
11 Composition root The single place where all module factories are called and wired to each other. There is exactly one. apps/​api/​composition-root.ts
12 Bus A map from a request class to the function that answers it. It lets one module ask a question without importing the answer's file. apps/​api/​core/​infrastructure/​buses/​
13 Contract The only thing one module may import from another: types, ports and query classes — never implementations. packages/​contracts/​modules/​<name>/​

The six that get broken first

  • Never accept an id from a client when creating — Id.create() server-side.
  • Save, then publish. Never publish inside a transaction.
  • Another module is a contract query, a port or an event — never an import of its files.
  • On a public read the filter is the authorization, not the middleware.
  • Guards belong on the aggregate, not in the controller.
  • Two modules, one endpoint: the app service owns the transaction.
