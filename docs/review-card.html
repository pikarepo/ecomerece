Definition of done.

The twelve checks from §07 of the guide, in the order a diff arrives. An unticked box is a question, not a veto — ask where the rule should live, then point at the file that already does it.

§07 · twelve checks

01 Domain & contracts the diff can be read without the API

  • Contract first. Cross-module query and port classes live in packages/contracts, and the providing module re-exports the query class instead of redeclaring it.
  • Aggregate shape. Private constructor, static create / rehydrate, private state, and command methods that raise events instead of returning them.
  • Value objects at the edge. Every input is converted to a VO in the app service; no raw string or number reaches the aggregate.
  • Ids. Id.create() on every create path — a client-supplied id in a create body is a bug, not a convenience.

02 Persistence & events what the database and the buses see

  • Mapper both ways. Aggregate ↔ document ↔ read model, both directions, with no database calls inside it.
  • Versioned save. Repository extends MongoRepository; Save filters on version and throws ConcurrencyError when it loses.
  • Publish after save. Events go out after the save — and after commit, if the use case uses UnitOfWork. Never inside the transaction.

03 Edge, wiring & proof what the next reader inherits

  • Controller. Extends BaseController, parses with Zod, holds no business rules, and is mounted with the right guards in the right order.
  • Module factory. Takes its deps (Buses + ports), builds the graph, registers handlers, and reads no env vars.
  • Wiring. Instantiated in createApplication() and mounted in routes/index.ts — no import-side-effect wiring.
  • Proof. All five checks below pass, and the API boots once against a real database.
  • Docs. PROJECT_DOCUMENTATION.md / TODO.md updated if the architecture moved; endpoints table and event catalog match the module.

Proof, in this order — do not reorder

bun run lint→ bun run typecheck→ bun test→ bun run arch→ api build + smoke boot

Rules. A red check is the finding — fix the cause, never the assertion, the type or the lint rule. arch failing means an import crosses a layer; that is the review, already automated.

Say what to do instead — three that come up weekly

  • This reaches into another module's files. Move the query class to packages/contracts and have the provider register it on the bus.
  • Drop the id from the create body — Id.create() belongs in the app service; the client only addresses resources that already exist.
  • save has to filter on version and throw ConcurrencyError. Without it, two concurrent edits both win and the second silently erases the first.
If you cannot check a box, say which one and why. “Looks fine” and “LGTM” are not reviews here: name the rule, the file, and the smallest change that satisfies it — the author can act on that, and the next reviewer can verify it.
